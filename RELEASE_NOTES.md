Fast DDS with four shared-memory transport fixes and an opt-in host id override (see the README): one package per ROS 2 release and architecture, each a drop-in replacement for the ROS apt package of the same version with `+husarion7` appended. Verify downloads against `SHA256SUMS`.

v5 adds `FASTDDS_HOST_ID` on Jazzy (Fast DDS 2.14.7). Fast DDS derives the host id that every shared-memory locator carries from the IPv4 addresses a process sees when it starts, so processes started before and after a robot's Ethernet gets carrier or a DHCP address disagree on it and a shared-memory-only world splits into islands. Set `FASTDDS_HOST_ID` (0 to 0xFFFF, decimal or 0x hex) to the same value in every process that shares a host's `/dev/shm`, and a different value on every host, and the id no longer depends on the addresses. Without the variable a v5 process behaves exactly like v4. Humble (2.6.12) and Lyrical (3.6.2) are rebuilt from the same sources and patches as v4, with the new version suffix. A v5 process can share a world with v2 to v4 processes as long as they compute the same id: without the variable that is the address hash, as before.
