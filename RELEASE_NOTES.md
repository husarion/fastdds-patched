Fast DDS with four shared-memory transport fixes (see the README): one package per ROS 2 release and architecture, each a drop-in replacement for the ROS apt package of the same version with `+husarion6` appended. Verify downloads against `SHA256SUMS`.

v4 adds a fourth fix for Jazzy (Fast DDS 2.14.7): a robot whose shared-memory profile allows messages above 64 KiB (the UGV OS robot profile allows 512 KiB) could lose the last 60 bytes of a large sample, about one random sample in 256 between 64 KiB and 512 KiB. Fragmented samples above that were lost at a few percent with best effort, and a sample filled with the byte 0x80 never arrived. A sample cut this way is delivered without error and reliable QoS does not repair it. With v4 every such sample arrives whole. Humble (2.6.12) and Lyrical (3.6.2) do not have this bug and are rebuilt from the same sources and patches as v3, with the new version suffix. The fix sits on the sending side, so every process that publishes large samples needs the package. Install it in every image whose processes share the robot's `/dev/shm`, as before. A v4 process can share a world with v2 and v3 processes: the shared-memory layout and the lock protocol do not change.
